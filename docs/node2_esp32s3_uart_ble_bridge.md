# Node 2 – ESP32-S3 UART to BLE Bridge

## Overview

Node 2 is the communication gateway of the acquisition system.

It receives validated binary frames from Node 1 over UART and forwards them wirelessly to Node 3 using Bluetooth Low Energy (BLE) notifications.

This node is implemented on a **Seeed Studio XIAO ESP32-S3**.

---

## Main Functions

Node 2 performs the following tasks:

1. Receive UART frames from Node 1
2. Reconstruct and validate the incoming frame structure
3. Check frame integrity using CRC8
4. Count valid frames and CRC errors
5. Forward valid frames over BLE notifications
6. Print debug information over Serial
7. Optionally show simplified status on OLED when the XIAO Expansion Board is attached

---

## Hardware

Board:

- **Seeed Studio XIAO ESP32-S3**

Optional:

- **Seeed Studio XIAO Expansion Board**
- Integrated OLED display (detected automatically by firmware)

## UART Configuration

Node 2 receives frames from Node 1 through UART.

### Pin assignment

- `D7` → UART RX
- `D6` → UART TX
- `GND` → common ground with Node 1

### UART parameters

- **Baud rate:** `115200`
- **Format:** `8N1`

---

## BLE Configuration

Node 2 operates as a **BLE Peripheral / GATT Server**.

### BLE device name

- `NODE2_BRIDGE`

### Service UUID

- `6e400001-b5a3-f393-e0a9-e50e24dcca9e`

### Characteristic UUID

- `6e400003-b5a3-f393-e0a9-e50e24dcca9e`

### Characteristic property

- `NOTIFY`

This allows Node 2 to push each new valid frame automatically to Node 3.

---

## Frame Handling

Node 2 expects the same binary frame format generated by Node 1.

### Frame format (11 bytes)

| Byte | Field |
|------|------|
| 0 | Start byte (`0xAA`) |
| 1 | Type |
| 2–5 | Timestamp (`uint32`) |
| 6–9 | Current (`float`) |
| 10 | CRC8 |

### Processing sequence

1. Read bytes from UART
2. Detect frame start (`0xAA`)
3. Store bytes until the full 11-byte frame is received
4. Compute CRC8 over bytes `1..9`
5. Compare with received CRC byte
6. If valid, decode timestamp and current value
7. Forward the raw frame through BLE notification

---

## Serial Debug Output

Node 2 provides continuous diagnostic information over Serial.

### Reported fields

- `FramesOK` → total valid frames received
- `CRCerr` → total CRC errors
- `BLE` → BLE connection state
- `rate` → valid frames per second
- `bytes` → UART bytes received per second
- `age` → time since last valid frame
- `t` → timestamp of last frame
- `I` → last current value

### Example

```text
FramesOK=1200  CRCerr=0  BLE=ON  rate=10 frm/s  bytes=110 B/s  age=15 ms  t=120.345s  I=1.2034A
```

---

## Optional OLED Debug

If an OLED is detected through the XIAO Expansion Board, Node 2 displays a simplified status summary.

### Displayed fields

- valid frame count
- CRC error count
- BLE connection state
- last current value

### Example screen

```text
NODE2 UART->BLE
Frames:1200
CRC:0
BLE:ON
I:1.203A
```

If no OLED is found, the firmware continues working normally and only Serial debug is used.

---

## Role in the System

Node 2 is the wireless communication bridge of the 3-node architecture:

```text
Node1 (SAMD21 sensor node) -> UART -> Node2 (ESP32-S3 bridge) -> BLE -> Node3 (ESP32-S3 receiver)
```

This design cleanly separates:

- sensor acquisition
- wired transmission
- wireless forwarding
- final BLE reception
